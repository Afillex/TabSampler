## Guitar-TECHS's labels, checked against its audio (Task 2)

`data/guitartechs.py` reads a take's MIDI, one track per string (`e B G D A E`); fret = pitch −
the string's open pitch. `scripts/check_guitartechs.py` checks the labels against the
direct-input audio, with GuitarSet's player 00 as the control (onset lag +11.6 ms — the
measure reads a frame late — and **0.949** of its pitches confirmed by the audio: the constant-Q
energy over 30–150 ms after the onset beats a semitone either side).

- **Single notes (players 1 and 2):** 279 notes, all confirmed, none overlapping, none dropped.
- **Player 3's musical excerpts:** 12 takes, 8.5 minutes, 1,940 notes. Per take, 0.54–0.92
  confirmed; 484 notes start while the string's previous note still sounds.
- **What those are:** every overlap is 3–4 ms and changes pitch — the pickup's note-off arriving
  just after the next note-on, harmless once each note's end is cut at the next onset. The
  unconfirmed notes are mostly very short: median 53 ms, against 402 ms for confirmed ones; 247
  of the 478 last under 60 ms, against 65 of the 1,462 confirmed. That is the pickup's pitch
  tracking emitting glitch notes. A duration floor would remove about half the bad labels and
  4% of the good ones; the rule waits for the scales, chords and techniques, still downloading.

## Basic Pitch was trained on GuitarSet (ADR 0055)

Its paper's Table 1: GuitarSet 648 files for training, 72 for testing — 90%, chosen at random —
and the installed package's `data/README.md` lists GuitarSet among "the datasets used to train the
original model". So every E1 and end-to-end figure on GuitarSet since Phase 0 is partly in-sample
for the transcriber; oracle mode is untouched. The README now labels them, and transcribers are
compared and tuned only on Guitar-TECHS's player 3 and EGDB. The GAPS benchmark model, the one
known guitar transcriber reported zero-shot on GuitarSet, is unreleased.

## Task 2 — where the end-to-end loss goes (`scripts/analyse_e2e.py`)

| | Guitar-TECHS player 3 (DI) | GuitarSet player 00 (mic, labelled) |
|---|---|---|
| reference / transcribed notes | 1,629 / 2,456 | 13,223 / 12,671 |
| missed (short / long) | 353 (217 / 136) | 3,872 (1,252 / 2,620) |
| extra (octave near / none near) | 1,180 (227 / 261) | 3,320 (1,312 / 830) |
| gap from note errors / context | 0.2137 / 0.0167 | 0.2408 / 0.0966 |

On electric direct input Basic Pitch **adds** notes — precision about half; on the acoustic
microphone it **misses long notes**, chord tones mostly, and its errors cost the decoder more
context. Predictions: note errors carry most of the gap (held on both); context a quarter or less
(held on player 3, failed on player 00, 29%); player 3's misses mostly short (held, 217 of 353).

## Task 3 — Basic Pitch's thresholds, chosen on player 3

30 settings, pre-registered rule (c735418). The defaults (onset 0.5, frame 0.3, min 127.7 ms): E1
0.6247, E2 0.3491. The best, **onset 0.7 / frame 0.4 / min 58 ms: E1 0.7737, E2 0.4185, +0.0694
[+0.0081, +0.1303]**, no clear chord-shape drop — adopted. It sat at the grid's edge, so 12
settings past it were pre-registered too (b1b5e1c): the best, 0.75 / 0.5 / 58, gained +0.0033
[−0.0459, +0.0791] — not adopted; E2 is flat from 0.7 to 0.8 and falls after.

`compare_validation.py` refused the first comparison: its bootstrap assumed both sides count the
same notes, true in oracle mode, false end to end. `paired_ratio_bootstrap` (`eval/bootstrap.py`)
pools each side over its own counts on the same resampled takes, and is the old bootstrap exactly
when the counts agree (a test pins it). **Metric-adjacent code: flagged.**

Caveats: the best of 30 on 12 takes is flattered; and a stricter setting that helps electric
guitar, where Basic Pitch adds notes, may hurt acoustic, where it misses them — which nothing clean
can measure yet: the only labelled acoustic validation, player 00, is in Basic Pitch's training.

## Task 4 — fine-tuning Basic Pitch (ADR 0056)

Ege chose TensorFlow beside Basic Pitch. Installing it into the inference environment would have
re-resolved librosa and coremltools under the cached transcriptions, so it has an environment of
its own (`scripts/setup_transcriber_training.sh`, TensorFlow 2.15, coremltools 9.0), and the
fine-tuned model is converted to CoreML and run by the unchanged CLI with `--model-path`. The
released weights copy into a freshly built model exactly (1.2e-7) and convert to CoreML as closely
as the shipped package does (about 1e-5). Targets follow Basic Pitch's own MAESTRO pipeline —
mirdata's `to_sparse_index` on its grids (`scripts/prepare_transcriber_data.py`); training
(`scripts/finetune_basic_pitch.py`) starts from the released weights with its loss.

**A check that proved nothing.** I first "verified" the CLI path by exporting the released weights
and getting identical notes on all 12 of player 3's takes — and the first fine-tuned measurement
then matched the released model to the last digit. basic-pitch ignores `--model-path` whenever
`--model-serialization` is given, and the adapter always gave it: both runs measured the released
model. The adapter now passes a model alone; the cache key's prefix changed so the 12 mislabelled
transcriptions can never be found; and the check was redone with a negative control — the released
export identical on 12 of 12 takes, the fine-tuned model different on 12 of 12. The mislabelled
measurement was never recorded.

**Measured (pre-registered, 6716ae4):** 30 epochs, best at 27; player 3's loss 1.2491 → 1.0149
(−18.8%, held). At the released model's thresholds the fine-tuned model writes 9,858 notes where the
released one writes 1,951: E2 0.4185 → **0.0946**, −0.3239 [−0.4294, −0.2057]. Fine-tuning moved
the posteriors' scale — plausibly the class-weighted onset loss (0.95 on positives, as the paper
describes it, though `train.py`'s default is unweighted). H2 and its prediction failed. Task 4b
gives the fine-tuned model its own thresholds, as Task 3 gave the released one.

## D14 — the app surface (ADR 0058)

A local web page served by the package (`tabsampler serve`, `make serve`): FastAPI, uvicorn and
python-multipart in a `web` dependency group, `127.0.0.1` by default, a warning for any other host.
One pipeline function, `tabsampler.pipeline.transcribe_path`, is what both the CLI and the server
call, so they cannot drift. Confidences are shown as a ranking — uncertain notes in parentheses
with a dashed outline, a certainty rank and the alternatives on hover or focus — never as a
percentage, because the end-to-end calibration error is 0.1841 (ADR 0057). Plain HTML, CSS and
JavaScript, nothing from the network.
