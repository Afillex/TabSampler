# 2026-10-03 — E3 becomes a measure, a decoder per style, the first C3 features

Branch `eval-label-and-c3`, plan `docs/plans/2026-10-03-timing-stretch-style-features.md`.
Ege approved the four open items of the hand-window session and Phase 2 task C3. Every run
was pre-registered in a commit made before it ran, and every validation comparison stated
its tolerance in advance and used a song-level paired bootstrap (ADR 0028's lesson).

⚠️ **Metric code changed on this branch**: E3's move timing (ADR 0029), the hand stretch
that E3 shares with the decoder (ADR 0030), and E3's speed limit, 12 → 48 frets per second
(ADR 0031). GuitarSet was read once, logged: the pre-registered evaluation in Task 10.

## Tasks 1–2 — the `eval-m1` label, and tools to compare decoders

`eval-m1` wrote "hand-set weights" into every row; rows now state the decoder's weights and
temperature, and the two 2026-10-01 rows carry a visible correction. `eval/recovery.py`
keeps recovery counts per song and part, and `eval/bootstrap.py` compares two decoders on
the same songs. The new counter reproduced the old validation figures exactly.

## Task 3 — E3 times a move from the last fretted group (ADR 0029)

A move after an open string used to be timed from the open string. On the same 16,732,524
human moves as ADR 0025's gate: **0.9795 → 0.9823. Prediction held** (rises, stays below
0.99).

## Task 4 — a wide chord stretches the hand (ADR 0030)

The hand is now a fret range, `(index, highest)`; the oracle was rewritten from the ADR's
text first, as a literal search over window starts. **Recovery did not change at all** on
the 300 validation songs (the decoder almost never picks a shape wider than four frets);
human tab's E3 stayed at 0.9823 to four places. Lattice 2.730 → 2.844 nodes per state;
`decode` 113.7 → 120.1 ms per 500 groups.

## Task 5 — E3's speed limit, measured (ADR 0031)

The slowest limit under which 99.86% of training artists' human moves pass — the chord
rules' rate — is **48.00 frets per second**. On unseen artists 0.9988 pass at it, above the
0.9976 required: **held**. E3's limit is 48. On the shipped training list, mostly
in-sample, human tab passes 0.9987. *(Corrected after review, ADR 0036: 99.86% is a share of
transitions, most of which move nothing; of the moves where the hand actually shifts, 98.6%
pass on unseen artists — 77% did at 12 frets/s.)*

## Tasks 6–7 — a decoder per style, each with its own temperature (ADRs 0032, 0033)

| validation parts | hand-set | fitted on that style | delta, 95% interval | chord shapes |
|---|---|---|---|---|
| clean | 0.8257 | **0.8616** | +0.0359 [+0.0134, +0.0622] | −0.00010: **passes** |
| distorted | 0.5705 | **0.6480** | +0.0774 [+0.0358, +0.1177] | −0.00065: **fails** (0.0005 allowed) |

The clean fit is `configs/decoder_clean.yaml`, the CLI's default; the distorted decoder
keeps the hand-set weights. Temperatures by per-note NLL on each style's parts: **clean
1.1975** (calibration error 0.2478 at the pooled 2.9974 → 0.0757), **distorted 4.2982**
(0.0785 → 0.0601). **Held**: clean needs a lower temperature. For the clean decoder T = 1
would give an even lower error (0.0559); the method chooses by likelihood and was kept.

## Tasks 8–9 — the first C3 feature groups (ADR 0034)

| against the style's four-weight fit | clean | distorted |
|---|---|---|
| per-string preference | −0.0104 [−0.0244, +0.0026]: not kept | +0.0190 [−0.0052, +0.0420]: not kept |
| fret regions | +0.0022 [−0.0006, +0.0056]: not kept | +0.0256 [+0.0027, +0.0478]: kept |

The distorted region model beat the hand-set decoder by +0.1030 [+0.0494, +0.1552] and
failed the same chord-shape allowance (−0.00062), so **no decoder changed**. The per-string

trust. The 11-weight fitter reproduced the four-weight clean fit song for song.

## Judgement calls

## Found and fixed during the work

- One commit was made before reading `make check`'s exit status (a lint error); it was
  amended before anything was pushed, and every later commit was chained to the check.
- The fit script overwrote its list of feature groups with a count, crashing after every
  `--features` fit. Fixed, with a smoke test that runs the script's `main` on synthetic
  sequences — the scripts' first test of their own.

## Review of the whole branch

An independent review returned "with fixes": no critical findings; the hand semantics
agree across all five implementations, every number traces to a log or the cached
per-song counts, and every decision followed its pre-registered rule. Fixed, each with a
test that failed first where code changed:

- **7-string tunings crashed** once `string_bias` existed, even at zero. The string term now
  costs nothing unless a bias is set, refuses a seventh string clearly when one is, and the
  fitter says it models six strings.
- **The public wording of the speed limit overstated it** (above; ADR 0036).
- **`make eval-m1` ran the new default under M1's hand-set hypothesis**; it now names
  `configs/phase1_baseline.yaml`, and a test guards it.
- Two tests that could not fail (the timing regression test at 48 frets/s; the
  feature-subset test that started every inactive weight at zero) can now; the fitter's
  oracle check gained a span-6 case where the hand stretches; the comparison and speed
  scripts print exact counts wherever a pre-registered threshold applies.
- Fixing the speed script's printout surfaced one more defect: it took "the old limit" from
  E3's default, which this branch had changed to 48. It now names 12; a smoke test covers it.
- README wording: the missed chord-shape prediction is now reported, the +0.4-point
  end-to-end gain is called noise-sized, and two decisions prompted in part by earlier
  GuitarSet runs (the per-style temperature, the clean default) are disclosed as such.

Recorded, not fixed: ADR 0035's Context was corrected while being accepted without saying
so; ADR 0030's claim about a chord's own notes was too strong (ADR 0036); in the per-string
fits `high` and the string biases nearly overlap — for single notes the mean fret is close
to a linear function of the string — so fitted biases cannot be read as string preferences
alone; the bench figures (34.3 / 120.1 ms) are from one run, and the review's rerun gave
38.3 / 127.0 ms; `--weights-out` was added to the fit script outside the plan. Deferred:
four small robustness gaps (unknown or empty `active` names in `fit_weights`, an empty
bootstrap input, `string_bias`'s tuple guard, untested region edges).

# Later the same day — GuitarSet's player 00 becomes validation data

Branch `guitarset-validation-player`, plan
`docs/plans/2026-10-03-guitarset-validation-player.md`, after Ege chose to hold out one
GuitarSet player.

⚠️ **The data split changed** (ADR 0037, amending ADR 0003): player 00's 60 tracks are
validation data, players 01–05's 300 the test set. `data/splits.py` derives both from the
360-track snapshot and refuses a snapshot whose players are uneven; `eval-m1 --split
validation` never writes to the test-set log, and a test checks it. The test set was read
twice, both logged and pre-registered.

## The re-decision (ADR 0038)

On player 00 the clean-fitted default was +0.0232 better than the hand-set weights in oracle
E2, with a 95% track-level interval of −0.0030 to +0.0513, and lowered the chord-shape rate
by 0.00076 against 0.0005 allowed: it failed both conditions, so **the default is the
hand-set weights again**, with T = 1.5728 calibrated for them on DadaGP's clean parts
(ADR 0033's method). The clean fit is kept as `configs/fitted_clean_dadagp.yaml`.

The prediction ("the clean fit loses, as on all 360 tracks") held only through the rule:
on player 00 alone the clean fit was ahead, the reverse of the 360-track result, so the
other players must favour the hand-set weights more strongly. Player 00 is also much
easier than the rest (oracle E2 0.81 against 0.66). One held-out player is a noisy guide.

## The new test set

| players 01–05, 300 tracks | default (hand-set, T 1.5728) | previous (clean fit) |
|---|---|---|
| E2 oracle / end to end | **0.6559** / 0.4277 | 0.6258 / 0.4337 |
| E3 chord shapes | 0.9980 / 0.9912 | 0.9970 / 0.9899 |
| E3 transitions | 0.9997 / 0.9984 | 0.9995 / 0.9974 |
| E5 | **0.0794** / 0.2189 | 0.1260 / 0.3117 |

Every ADR 0016 value holds on the 300 for the default; M2 is 10.4 points away. These
tracks were part of the earlier 360-track runs, so their oracle E2 was derived before the
runs (0.656, 0.6257) and came out at 0.6559 and 0.6258: a check on the arithmetic, not on
the choice.
