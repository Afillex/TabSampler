**What it argues.** The single largest pattern is an open string where the player stayed in
position and fretted the note; the default rewards every open string (open_reward 0.25)
wherever the hand is. Question 7 says these are rarely a passage moved down the neck: in
688 of the 860 the decoder's hand was in the same region as the player's. Where the
decoder's hand was up the neck — 430 notes, a sixth of all errors, worth at most 3.3 points
of E2 on player 00 — a cost on open strings played there, the Phase 2 plan's "open strings
conditioned on the neighbouring shapes", can reach them. The 362 in open position it cannot:
there an open string and a fretted one are both idiomatic.

**Slip.** The first run counted one right note fewer than E2 (10,663): a unison on two
strings, 3 ms apart in `00_Jazz1-200-B_solo`, paired in order. Copies on the player's string
are now paired first (094356a, with a test); the answers above are from the rerun, which
agrees with E2 exactly.

## Task 2 — open strings played up the neck (ADR 0039)

Argued by questions 5 and 7. A shape costs `open_up_neck` per open string when the hand it is
played with has its index at fret 5 or above, charged with the move into the shape: the
scorer's `transition_cost_from` carries it, the fitter treats it as a feature of a lattice node
from the second group on, and the brute-force oracle charges it from the ADR's text. Moving
the oracle's threshold, or charging a passage's first shape, fails the tests.

**Ege's decision, before the run:** the chord-shape condition is now *no clear drop* — a
challenger fails it only if the whole 95% track-level interval of its chord-shape change lies
below zero — instead of the fixed 0.0005, which is three shapes of player 00's 6,607. The
per-track files keep each track's chord-shape counts for it.

- **The fit** (DadaGP's clean training parts, the base weights held): 0.7615, positive as
  predicted. Recorded, not ruled on: clean validation recovery 0.8257 → 0.8460.
- **Player 00** (rule committed in 81ee8c5, both configs in 420c088): oracle E2 0.8065 →
  0.8273, **+0.0209 [+0.0066, +0.0363]** — 276 more notes on the player's string; chord shapes
  6543 → 6541 of 6607, [−0.0011, +0.0003], no clear drop. **Adopted.** The old allowance would
  have given the same verdict. End to end +0.0039 [−0.0065, +0.0146].
- **Recalibrated** by ADR 0033's method: T = 1.2934. On player 00 the new default's E5 is
  0.0830 in oracle mode (0.1178 before) and 0.2387 end to end (0.2100 before).
- **Task 1's analysis on the challenger:** open strings where the player fretted, 860 → 663;
  with the decoder's hand up the neck 430 → 97, in open position 430 → 566 — it now sometimes
  moves down the neck to take an open string. Every style improved, and comping and soloing;
  notes at fret 12 and above lost ten.

**Not measured on the test players.** The README's test table is labelled as the hand-set
default's; the new default's figures wait for the one pre-registered evaluation of task C6.

## C4 — a learned model (ADRs 0041–0044)

Ege judged C3 run through and chose to start C4. Decided first: **D11** (ADR 0041) — PyTorch
2.14.1 in a `model` group, the CPU-only build on Linux so CI stays small, the M4's CPU first;
and **D15** (ADR 0042, Ege's decision) — weights trained on DadaGP stay unpublished, the code
and results public. The design (ADR 0043): today's decoder plus a learned cost per lattice node
from a bidirectional GRU over the note groups, the CRF kept as the output layer.

Built in five tested steps (`docs/plans/2026-10-04-c4-learned-model.md`): the lattice as arrays,
pinned to the fitter's features and the oracle's path cost; the CRF in torch, whose NLL and
gradient equal the fitter's to 1e-9 and whose Viterbi cost is the decoder's; the network, which
starts exactly at the default and which padding cannot reach; training, which checkpoints and
resumes bit-identically; and the evaluation on player 00, where the untrained model placed
every note as the default does.

**The run** (pre-registered in 227ca87): the clean parts of 1,500 training songs, 336,315
groups. DadaGP's clean validation NLL per group fell 0.4327 → 0.3136 (epoch 13 of 16) —
hypothesis 1 held. On player 00:

| | oracle E2 | against today's decoder |
|---|---|---|
| (a) today's decoder | 0.8273 | |
| (b) the learned term alone | 0.4652 | −0.3622 [−0.4162, −0.3054] |
| (c) the learned model | 0.7970 | −0.0303 [−0.0861, +0.0199] |

**Hypothesis 2 failed: not preferred**, and the prediction failed low (ADR 0044). The model
fitted DadaGP better and GuitarSet's player worse — the proxy again, not the capacity. Looked at
after the result and not used to choose: it gained on bossa nova, jazz and soloing and lost on
rock, singer-songwriter, funk and comping.

**Slip.** The first training job was stopped at the default 30-minute background limit after
epoch 10. It resumed from its checkpoint — the resume is tested to be exact — and long jobs now
get the two-hour limit.
