# 2026-10-02 to 10-03 — The hand as a window, an artist-disjoint split, a calibrated default

Branch `hand-window`, plan `docs/plans/2026-10-02-hand-window-and-calibration.md` (Phase 2
plan tasks C1, C2 and C5). Every reported number was pre-registered in an ADR, script or
config committed before it ran. **Both pre-registered checks on the window were missed**,
and Ege kept the window both times. The calibration hypothesis held, the re-baseline's held
only in part, the fitted weights failed their fair test, and the one GuitarSet run missed
its prediction twice. All of it is below, with what a review of the whole branch found.

⚠️ **Metric code and splits changed on this branch:** E3's transition rule (Task 4) and a
new DadaGP split (Task 2). GuitarSet was read twice, both logged: the lattice measurement
(instrumentation, no metric) and the one pre-registered evaluation.

## Task 2 — an artist-disjoint split (ADR 0024)

Whole artists go to one side, by the SHA-256 of the case-folded artist folder; frozen by
hash (`538be675…`). 4,347 training artists and 519 validation; 19,794 and 2,240 cleared
songs. Every fit, calibration and validation from now on uses it.

Re-baseline, point hand model, 300 validation songs (505,847 notes). **The hypothesis held
only in part.** Its first clause held: the shipped split's pattern survives the move to
unseen artists.

| | overall | clean | distorted |
|---|---|---|---|
| hand-set | 0.6385 | **0.8217** | 0.5728 |
| fitted (600 training songs) | **0.6457** | 0.6591 | **0.6409** |

Its second clause — the shipped split's artist overlap inflated the fitted score "by little,
if at all" — is not supported. It was first recorded as held, by comparing the fitted
weights' 0.6457 here with 0.6456 on the shipped split. The two validation sets differ: the
hand-set weights, which artist overlap cannot help, moved from 0.6196 to 0.6385. Measured
against them, the fitted advantage fell from +2.60 points to +0.72 — what inflation would
look like. The training songs differ too, so the comparison is inconclusive either way. The
row in `results.csv` carries the correction.
## Tasks 3–4 — the window, and E3's transition rule on it (ADR 0025)

`fingering.states.shift_window` is the single definition: the hand covers frets h to h + 4,
moves by the least distance that brings a shape inside, anchors a wider shape at its lowest
fret, and stays put for an all-open shape. E3's transition rule now uses it, which also
fixes the old defect where E3 did not carry the hand across an all-open shape.

**Acceptance gate, fixed in advance: human tab passes at ≥ 0.99. Missed: 0.9795** on
16,732,524 human moves (point model 0.8835). The window removed 82% of the failures. An
exploratory breakdown on 2,000 songs: 47.7% of what is left are shifts of one or two frets
and 64.8% are at 24 frets/s or less — mostly small, quick shifts that the 12 frets/s speed
limit calls impossible. **Ege's decision: keep the window, fix the speed limit later.** E3's
transition rate keeps ADR 0022's caveat until then.

Found in review, and not separated from that breakdown: E3 times a move across an all-open
shape from the open shape, not from the last fretted one. `fret 2 → open → fret 10` at
0.25 s steps fails at 16 frets/s, while `fret 2 → fret 10` in the same 0.5 s passes. Some of
the remaining 2% may be this artefact rather than the speed limit, so the speed-limit
experiment has to fix the timing first.

## Task 5 — decoder, cost model, fitter and oracle on the window

The brute-force oracle was rewritten from ADR 0025's text first; Viterbi, forward-backward
and the fitter all agree with it. Every shape now gets one lattice node per reachable window.

| | point model | hand window |
|---|---|---|
| lattice nodes per state, 60 GuitarSet tracks' reference notes | 1.072× | 2.569× |
| `viterbi` / `decode`, 500 groups | 7.2 / 58.3 ms | 32.6 / 113.7 ms |

The golden clip moved from frets 12, 0, 12, 0, 10, 0, 8, 8 to **7, 0, 7, 0, 10, 0, 8, 8** —
7th position with no shift at all. Moves are no longer symmetric (3 → 9 moves the window 2
frets, 9 → 3 moves it 6), so a test that asserted symmetry was replaced by one that pins
both values.

## Task 6 — does the window help the default? (pre-registered: must not lower recovery)

| hand-set weights | clean | distorted | NLL / group |
|---|---|---|---|
| point model | 0.8217 | 0.5728 | 0.7489 |
| hand window | **0.8257** | 0.5705 | **0.6937** |

**Failed, by 0.0023 on distorted parts.** The rule set no tolerance and no noise estimate
was made. The comparison is paired, the same notes under both models, so the drop may be
real; whether it is noise is unknown. **Ege kept the window**; ADR 0028 records the check
and the decision.

## Task 7 — the fitted weights' fair test (ADR 0027) and the default's temperature (ADR 0026)

Refitted under the window: move 1.0143, span 0.6149, high 0.2511, open_reward −0.8487.
Against the hand-set weights on validation: clean 0.6919 vs 0.8257 (**fail**), distorted
0.6149 vs 0.5705 (pass), decoded chord shapes 0.9987 vs 0.9998 (**fail**). **Hand-set stays
the default**, and ADR 0023's open question is closed for these weights.

Temperature for the default, by per-note NLL on validation: **T = 2.9974**. Calibration
error 0.2017 → **0.0767**, per-note NLL 1.2156 → 0.7475. **Hypothesis held.** The script was
rewritten to build each lattice once and redo only forward-backward per trial temperature,
checked equal to the old scoring to 1e-10 before it ran.

## Judgement calls

- **Order of the code changes.** `shift_window` landed alone first and `carry_hand`
  switched with the decoder, so that every commit stayed green and E3's gate ran on
  committed code. Cost if wrong: none; the end state is the same.
- **The fair test before the fit.** ADRs 0026 and 0027 were committed before the window fit
  ran, so the fit's output could not shape the test. One fit then served both rules.
- **One README refresh, in Task 8**, so that GuitarSet is read once. The branch's
  intermediate commits describe older numbers, and none of them reach `main` alone.
- **ADR 0016's transition guardrail is reported, not enforced**: the rule it was set on is
  gone. The chord-shape rate, E2, E4 and E5 kept their definitions and were compared
  directly.
- **The window fit skipped the half-split stability check** (`--skip-halves`) to keep the
  run under half an hour. No pre-registered rule used the halves, and the point model's
  halves agreed within 5.7%. Cost if wrong: no stability check for the window weights.
- **The second check has its own record, ADR 0028**, rather than an addendum to ADR 0025.
  An accepted ADR is not edited, and the 2026-09-27 precedent allows only corrections made
  before review, not new decisions. ADR 0025 is unchanged since it was accepted.
- **`configs/fitted_dadagp.yaml` keeps the point-model weights** as ADR 0023's record; the
  window refit's weights are in `results.csv`. Its header now says it reproduces only at
  commit e809798.
- **Results-row notes corrected after review say so in the row.** Three notes overstated
  what was measured or gave a stale reason; no number changed.
- **The GuitarSet rows were left exactly as `eval-m1` wrote them.**

## Review of the whole branch

Fixed, each with a test that failed first where code changed:

- **The split default.** ADR 0024 says every fit uses the artist split, but `load_tracks`
  and both DadaGP scripts defaulted to the shipped one. The scheme is now required in the
  loader, and the scripts refuse to run without `--split`.
- **A vacuous test.** The artist-scheme loader test put both of its artists on the training
  side, so it passed whether the scheme was honoured, ignored or reversed. It now uses two
  songs the shipped and artist splits place on opposite sides, and fails on both mistakes.
- **The oracle never saw a shape wider than the window**: every oracle test ran at span 4,
  while the default allows 5. Two oracle tests now run at span 6. With the anchoring of wide
  shapes deliberately broken, the new forward-backward test fails and all seven older oracle
  tests pass — that was the gap.
- Stale decoder docstrings, missing supersession pointers (ADRs 0011, 0018, 0022, 0023) and
  a self-referencing index row, the over-claimed re-baseline, and the fitted config's
  reproduction claim in the README.

## Found, not fixed (outside the plan)

- **`eval-m1` writes "hand-set weights (ADR 0012)" into every row's notes** and prints
  "ground-zero number" whatever the decoder config is. The 2026-10-01 fitted-weights rows
  therefore say the wrong thing in their notes; their config column is right. The fix is
  small and needs a test; annotating the old rows is Ege's call.
- **E3's timing across open shapes** (Tasks 3–4 above). Fixing it changes the metric after
  its one GuitarSet look, so it belongs with the speed-limit experiment, pre-registered.
- **Uncertainty marks.** On the golden phrase every note is below the 0.6 line (ADR 0013) at
  T = 1, with posteriors 0.37–0.56, as well as at T = 2.9974, with 0.30–0.41: there the marks
  come from the window's equal-cost alternatives, not the temperature. How many real notes
  change has not been measured.
- **A chord wider than the window, alternating with its own top note**, moves the window a
  fret each way under ADR 0025's anchoring: (12, 17) → 17 → (12, 17) is charged two frets
  of movement a player would not make.
- **E3 reads the window from the same constant as the decoder** rather than from
  `PlayabilityRules`, so changing the decoder's window would silently move the metric.
- **ADR 0016's transition guardrail has no baseline under the new rule.** A short ADR could
  set one from this run's figures.

## Open questions, all Ege's

1. **The speed limit.** Pre-register an experiment on the 12 frets/s limit, with the
   open-shape timing fixed first — together, the reason E3's transition rate is still not a
   playability measure.
2. **One temperature or two.** Oracle E5 did not move on clean GuitarSet, and the
   temperature was fitted on mostly distorted validation parts. Calibrating per style is a
   validation question, and belongs with task C3's style work.
3. **The oracle chord-shape breach (0.0003).** It cannot be diagnosed on GuitarSet. On
   DadaGP validation the window left the decoded chord-shape rate at 0.9998.
4. **Wide chords and the window.** Whether a shape wider than 4 frets should stretch the
   window rather than anchor it — a change to ADR 0025's model, so a decision first.
