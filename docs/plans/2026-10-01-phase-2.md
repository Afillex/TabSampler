# Tab Sampler — Phase 2 Plan: a fingering model that reaches M2

> Tasks are executed in order; steps use checkbox (`- [ ]`) syntax for tracking. Every run
> that produces a reported number is pre-registered in a committed script or config first.

**Goal:** reach M2 — **oracle E2 ≥ 0.760 on GuitarSet** (ADR 0016), with E4 = 1.0000, the E3
chord-shape rate not below the baseline, and end-to-end E5 below 0.3851.

**Spec:** `docs/spec.md`. **Data:** DadaGP v1.1 under ADR 0021. ProgGP did not arrive.

---

## Where this starts

| GuitarSet | oracle E2 | e2e E2 | e2e E5 |
|---|---|---|---|
| hand-set weights (default) | 0.6599 | 0.4318 | 0.3851 |
| fitted on DadaGP, T = 1.721 (ADR 0023) | 0.6988 | 0.4603 | 0.1411 |
| **M2 target** | **0.760** | — | — |

Four refitted scalars closed 3.9 of the 10 points. The rest needs a better model — and
2026-10-01 produced four findings that say where to look.

## What the first DadaGP session established

1. **Playing style changes fingering, a lot.** On DadaGP validation the hand-set weights
   recover 81% of human fingerings on clean parts and 54% on distorted ones; the fitted
   weights trade 11 points of clean for 8 of distorted. One set of weights for all styles
   is leaving accuracy on the table — but **at inference on audio the style is not known**,
   so a style-aware model needs the style as an input (a user setting, as ADR 0008 did for
   tuning) or has to infer it.
2. **The movement feature is mis-specified** (ADR 0022). "Hand position = lowest fretted
   fret" counts a finger reaching inside one position as the hand moving. Human tab fails
   E3's speed rule 12% of the time for that reason alone, and the cost model's movement
   term charges the same phantom movement.
3. **Per-note confidence needs its own calibration.** Path-level likelihood left the
   posteriors overconfident; a temperature of 1.72 fixed most of it.
4. **No validation proxy has yet predicted GuitarSet reliably.** The pooled DadaGP
   validation rule pointed the right way; the clean-parts breakdown pointed the wrong way.
   Choosing a better proxy is a decision to make on principle before a run — never by
   checking which proxy agrees with GuitarSet.

### Task C1: An artist-disjoint split — required before any model with capacity

**Why:** 1,164 of 4,869 artists sit on both sides of the shipped split (ADR 0021). Four
scalars cannot memorise an artist; a neural model can, and its validation score would be
inflated by artists it has already seen.

- [x] Write ADR 0024: assign whole artists to training or validation (seeded, ~10% of notes
      to validation), freeze by hash exactly as ADR 0021 froze the shipped split.
- [x] Extend `data/dadagp.py` with the new split; tests on a synthetic archive.
- [x] Re-measure the fitted CRF on the new validation set, so later models have a baseline
      on the same footing. *(Done 2026-10-02: hand-set 0.6385, fitted 0.6457; see
      `experiments/results.csv`.)*

### Task C2: Model the hand as a window, not a point

**Why:** finding 2. **Acceptance test, fixed in advance:** human tab passes the new E3
transition rule at ≥ 99%, the standard the chord rules already meet.

- [x] Write ADR 0025: a hand position covers a window of frets (start at 4, as ADR 0011's
      span limit); movement is charged only when a note falls outside the current window,
      by the distance the window has to shift.
- [x] Implement it in E3's transition rule and rerun `scripts/validate_playability.py`.
      Do not continue unless the acceptance test passes. *(It did not: 0.9795. Ege chose to
      continue and to settle the speed limit separately; ADR 0025 records both.)*
- [x] Replace the cost model's movement feature with the window shift. The brute-force
      oracle changes with it (ADR 0014), written from the ADR's text, not copied from the
      implementation.
- [x] Refit the four weights (`scripts/fit_cost_weights.py`) and compare on validation.
      *(They lost ADR 0027's fair test; the hand-set weights stay the default.)*

### Task C3: Richer features, same CRF

**Why:** `fingering/fit.py` already fits any feature linear in its weights, with exact
gradients and oracle tests. Adding features costs little and keeps the model interpretable.

- [ ] Candidate features, each argued before it is tried: a per-string preference; fret
      region (open position, middle, above 12); open strings conditioned on the neighbouring
      shapes; the window shift from C2. *(2026-10-03: per-string preference and fret regions
      tried, ADR 0034 -- neither adopted; open strings conditioned on neighbours not yet.)*
- [x] One feature group per experiment, each with a written hypothesis and its validation
      gain recorded. Keep a feature only if it improves validation recovery.
- [x] **Style:** fit on clean and distorted parts separately and measure each on its own
      validation parts. Whether the shipped decoder then asks the user for a style, or
      marginalises over both, is a decision with its own ADR.

### Task C4: A learned sequence model — only if C2 and C3 plateau short of the target

**Why:** a CRF's features are hand-chosen. A neural encoder can learn context a feature
list misses, but it brings a framework, compute and a much larger evaluation burden.

- [x] **D11 first:** an ADR on framework and compute (`torch` 2.14 is verified available on
      Python 3.13). Not before C2 and C3 have been measured.
      *(ADR 0041, 2026-10-04, after Ege judged C3 run through; and ADR 0042 (D15):
      weights trained on DadaGP stay unpublished.)*
- [ ] Architecture: a bidirectional encoder over the note sequence, with the **CRF kept as
      the output layer**, so one-note-per-string and the chord lattice stay structural
      (ADR 0010) rather than learned.
- [ ] Train on C1's artist-disjoint training split; select on its validation split only.

### Task C5: Calibrate whatever ships

- [x] Temperature on validation by per-note NLL, as `scripts/calibrate_temperature.py`
      does, for the decoder that is actually going to be the default. *(Done for today's
      default: T = 2.9974, ADR 0026. Redo whenever the default changes.)* *(Redone
      2026-10-03 per style: clean 1.1975, distorted 4.2982, ADR 0033.)*

### Task C6: One GuitarSet evaluation against M2

- [x] Pre-register the config and hypothesis, commit, run `eval-m1` once, report the result
      against ADR 0016's target and every guardrail — including a miss. *(ADR 0045: oracle E2
      0.6819, M2 missed by 7.8 points; every other ADR 0016 value held.)*
      *(Pre-registered 2026-10-04, after ADR 0044, Ege's decision to close the phase: today's
      default through `tabsampler eval-m1 --split test --config configs/m2_c6_eval.yaml`, whose
      hypothesis holds every prediction; and the spec's comparison on the same tracks through
      `scripts/evaluate_model.py --split test --run cache/model/c4`, predicted to repeat
      player 00's order — (a) today's decoder above (c) the learned model, (b) far below. Two
      logged looks, nothing chosen from either.)*
