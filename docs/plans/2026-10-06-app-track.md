# The app track — a guitarist can use it (B1–B4)

> Tasks run in order; steps use checkbox (`- [ ]`) syntax. No task here produces a reported
> number, so nothing is pre-registered and no test set is touched.

**Status:** started 2026-10-06. Ege chose the app track after Phase 5 closed (ADR 0057); D14 is
decided by ADR 0058. Supersedes the B1–B4 sketch in `docs/plans/2026-09-27-rest-of-project.md`,
whose figures (ECE 0.37, E2 0.4231) are stale.

**Goal:** a guitarist drops a recording on a local web page and gets back tab with uncertain notes
visibly marked, alternatives on hover, and a MusicXML or Guitar Pro file to take away.

**Gate (Ege's sign-off, not self-certified):** Ege drops one of their own recordings into the page
and gets back tab with uncertain notes marked and alternatives on hover, and the page agrees note
for note with `tabsampler transcribe` on the same file.

**Architecture:** one pipeline function (`tabsampler/pipeline.py`) that both the CLI and a FastAPI
app call; the app serves one static page (HTML, CSS, JavaScript drawing SVG, no build step);
exporters in `render/` beside the ASCII and JSON renderers.

**Tech:** FastAPI 0.142, uvicorn 0.54, python-multipart 0.0.32 in a `web` group; httpx2 in `dev`
for FastAPI's test client (Starlette 1.7 deprecates httpx for it); pyguitarpro 0.11 in core. All four resolve on Python 3.13 (checked
2026-10-06 with `uv pip install --dry-run`).

## Where this starts

- `tabsampler transcribe audio [-o out.json]` wires the pipeline inline in `cli.py`: Basic Pitch at
  `CHOSEN_PARAMS` (ADR 0057) → `group_notes` → `decode_best_effort` with `HandSetScorer` →
  `render_ascii_with_legend` or `render_json`, then E3 and E4 printed.
- `render/json_out.py`'s `tab_to_dict` is ADR 0013's document, `schema_version` 1, rhythm stated as
  `time_positioned_only`.
- ADR 0017 (accepted) fixes the exports' rhythm: a 120 BPM grid, 480 divisions per quarter, 4/4,
  and the disclaimer in the file's bytes.
- What a user should expect, measured: EGDB end-to-end E2 0.4547, GuitarSet's test players 0.4553
  (labelled, ADR 0055); end-to-end calibration error 0.1841 on GuitarSet (ADR 0057).

## Global constraints

- `pyright --strict` on `src/`; untyped libraries confined to one small function each.
- CI stays offline and under 5 minutes: no test runs the transcriber or a browser.
- The `web` group is optional: nothing outside `tabsampler/web/` and `cli.py`'s `serve` imports
  FastAPI, and `serve` fails with a one-line install hint when it is missing.
- Bind `127.0.0.1` by default (ADR 0058).
- No number appears in the page or the docs that is not in `results.csv` or an ADR.
- No dependency beyond the five named above.

## Review Focus

1. **A confident-looking tab built from weak posteriors.** → Task 3 tests that the page says
   "uncalibrated", shows no percentage, and marks uncertain notes by shape as well as colour.
2. **An upload that is not guitar, not audio, or enormous** (a `.txt` renamed `.wav`, a 2 GB WAV, a
   40-minute podcast). → Task 2: 400 / 413 / 413, checked before the transcriber runs.
3. **The page and the CLI disagreeing.** → Task 1 makes them share one function; Task 3 checks one
   real file by hand both ways.
4. **An export that invents rhythm or folds the capo into frets.** → Task 4 tests the disclaimer in
   the bytes, the capo as a capo, and string/fret round trips.
5. **A silent note loss.** Degradation is reported by the CLI today; the page must show it too. →
   Task 2 returns it; Task 3 renders the banner.

**Files:** create `src/tabsampler/pipeline.py`, `tests/test_pipeline.py`; modify
`src/tabsampler/cli.py` (`transcribe` calls it).

**Produces:**

```python
class FileTranscriber(Protocol):
    def transcribe_file(self, path: Path) -> list[NoteEvent]: ...

@dataclass(frozen=True, slots=True)
class PipelineResult:
    tab: tuple[TabNote, ...]
    degradation: Degradation
    group_rate: float        # E3, groups
    transition_rate: float   # E3, transitions
    pitch_validity: float    # E4

def transcribe_path(path: Path, cfg: Phase1Config, transcriber: FileTranscriber) -> PipelineResult
```

An empty detection returns an empty tab, a clean `Degradation` and rates of 1.0 for an empty
input as `playability_rate` already defines them (check its behaviour on `[]`; if it raises, the
function returns before calling it and records rates as `nan`, and the CLI keeps its "no notes"
message).

## Task 2: Serve the pipeline over a local HTTP API (B2)

**Files:** create `src/tabsampler/web/__init__.py`, `web/app.py`, `tests/web/test_app.py`; modify
`pyproject.toml` (`web` group; `httpx2` in `dev`), `cli.py` (`serve`).

**Produces:** `create_app(cfg: Phase1Config, transcriber: FileTranscriber) -> FastAPI`, constants
`DEFAULT_HOST = "127.0.0.1"`, `MAX_UPLOAD_BYTES = 100 * 1024 * 1024`, `MAX_DURATION_S = 300.0`;
`GET /api/health` → `{"status": "ok", "transcriber_available": bool}`; `POST /api/transcribe`
(multipart field `audio`) → `tab_to_dict(...)` plus `"degradation"` (the `Degradation` fields
except `details`, which become a list of at most 20 strings) and `"metrics"`
(`group_rate`, `transition_rate`, `pitch_validity`, `n_notes_detected`).

The app takes the transcriber as an argument, so tests pass a fake and nothing monkeypatches a
module global. The upload is streamed to a temporary file in 1 MB chunks and refused at the first
chunk past the limit; the duration is read from the header (`soundfile.info`) before the
transcriber runs; the temporary file is deleted in a `finally`. The extension is kept, because
Basic Pitch reads by it.

## Task 3: The tab view, with uncertainty made honest (B3)

**Files:** create `src/tabsampler/web/static/index.html`, `app.js`, `style.css`,
`tests/web/test_static.py`; modify `web/app.py` (mount `/static`, serve `/`), `pyproject.toml`
if hatch needs the static files listed.

The page: a file input and drop zone → `POST /api/transcribe` → six string lines, high e on top,
notes placed by onset at a fixed pixels-per-second (horizontally scrollable, the page itself never
scrolls sideways), each note its fret number. Uncertain notes (posterior below the threshold, which
the API returns from the config) get parentheses and a dashed outline. Hover **or keyboard focus**
shows a tooltip: the pitch, the onset in seconds, and the alternatives in rank order as
"string, fret" — no percentages. A banner lists degradation counts when any is non-zero, and the
E3/E4 line the CLI prints. Fixed text: confidences are uncalibrated (a ranking, with the 0.1841
figure and ADR 0057 named), rhythm is not transcribed (ADR 0009), isolated guitar only (ADR 0002).
Errors from the API are shown as their `detail` text. Light and dark via `prefers-color-scheme`.

## Task 4: MusicXML and Guitar Pro export (B1, ADR 0017)

**Files:** create `src/tabsampler/render/musicxml.py`, `render/guitarpro.py`, `render/grid.py`,
`tests/render/test_musicxml.py`, `test_guitarpro.py`, `test_grid.py`; modify `render/json_out.py`
(`tab_from_dict`), `cli.py` (`-o` by suffix: `.musicxml`, `.gp5`), `web/app.py`
(`POST /api/export/{fmt}` taking the document back), `static/app.js` (two download buttons),
`pyproject.toml` (pyguitarpro).

**Produces:**

```python
DISCLAIMER: str   # ADR 0017's text, verbatim
TEMPO_BPM = 120; DIVISIONS = 480; BEATS_PER_BAR = 4
def to_grid(tab: Sequence[TabNote]) -> list[GridEvent]   # onsets and durations in ticks, chords
                                                         # merged, gaps as rests, bars split
def render_musicxml(tab: Sequence[TabNote], tuning: Tuning) -> bytes
def render_guitarpro(tab: Sequence[TabNote], tuning: Tuning) -> bytes   # GP5
def tab_from_dict(doc: Mapping[str, Any]) -> tuple[list[TabNote], Tuning]  # rejects other schema_versions
```

`grid.py` is pure and holds the arithmetic both exporters share; it is where the bugs will be, so
it gets the property tests. A note crossing a bar line is split and tied. MusicXML durations are
exact ticks; Guitar Pro has only standard note values, so its grid is the nearest 1/32 note,
stated in the GP file's notice beside the disclaimer — a real loss of precision, reported here
rather than hidden. Overlapping notes of different lengths in one chord take the chord's shortest
duration in Guitar Pro, which has no per-note duration within a beat; stated the same way.

- [ ] Tests first: `to_grid` — ticks sum to whole bars; every note's onset within half a tick of
      its time; a bar-crossing note splits and ties (hypothesis over random tabs). MusicXML —
      the disclaimer is in the bytes; parses with `xml.etree`; each note's `<string>`/`<fret>`
      match (MusicXML strings count 1 = high e); a capo 2 tuning writes `<capo>2</capo>` and
      frets stay relative; 120 BPM and 4/4 stated. Guitar Pro — `guitarpro.parse` of the bytes
      reads back the same strings and frets, the notice holds the disclaimer, and the capo is
      written as a capo — **find pyguitarpro's capo field in its installed source before writing
      this test**, and name where it was found. `tab_from_dict(tab_to_dict(t)) == t`. The export endpoint returns the right
      content type and filename and 400 on a bad document.
